# 活动策划天团 · 详细执行流程

> 主理人（campus-event-planner-team-lead）的操作手册。这份文档规定**每个阶段做什么、交给谁、等什么、怎么判断干完了**。

## 总览

```
用户输入
   ↓
Phase 0  需求澄清（主理人独做，30 秒）
   ↓
Phase 1  并行派单（4 角色同时开工）
   ├─ proposal-writer    → 一~六段 + 八总纲
   ├─ budget-analyst     → 七、预算 + Excel
   ├─ risk-manager       → 八、风险预案 + Excel
   └─ promo-copywriter   → 附录A 文案 + PPTX（异步）
   ↓
Phase 2  汇编（主理人读文件、填 HTML 骨架）
   ↓
Phase 3  交付前检查（9 项，逐条过）
   ↓
Phase 4  交付（present_files 打开 + 摘要 + 待确认清单）
```

---

## Phase 0：需求澄清

**目标**：拿到六要素，判断活动类型。**只做这一件事，不做别的。**

### 必查六要素

| 要素 | 为什么必须 | 缺失时怎么处理 |
|------|-----------|--------------|
| 名称 | 全篇标题 | 用"XX 社团 XX 活动"占位并标待确认 |
| **类型** | 决定整条节奏线（内部/对外） | **必须问**，这是分叉点 |
| 规模 | 决定物料、人力、预算基数 | 按类型给默认值（内部 50 / 对外 150） |
| 日期 | 决定筹备倒排 | 必须问，或给"TBD"并说明请示 |
| 场地 | 决定容量与布置 | 必须问，且要问**备选** |
| 可用人力 | 决定分工现实性 | 必须问实际能来几个人 |

### 类型判断（关键分叉）

| 判据 | 内部建设类 | 对外展示类 |
|------|-----------|-----------|
| 面向对象 | 仅社团成员 | 全校/校外 |
| 是否需要报备社团联 | 备案即可 | **必须正式报备** |
| 筹备周期 | T-10 起 | T-21 起 |
| 流程容错 | 高（灵活） | 低（每个环节要有备案） |
| 风险标准 | 常规 | 高一档 |

> ⚠️ 判断错误的典型后果：把招新摆摊当内部活动办，没报备、没雨天预案、没考虑人流。

### 澄清话术原则

- **一轮问完**，不要挤牙膏
- 问题不超过 3 个
- 能推断的不问（如"迎新破冰"必然是内部类、"招新"必然是对外类）
- 用户说"随便"或"你定"时：按最常见配置推进，并在交付时标注

### 出口条件

六要素全部有值（真实值或明确默认值），类型已判定。

## Phase 1：并行派单

### 派单三原则

1. **同一条消息内 spawn 全部 4 个成员**，不要串行等待
2. **每个 prompt 必须包含四样东西**：活动信息 / 知识库路径 / 脚本路径 / 回传格式
3. **明确说"调用脚本，不要自己写代码"**

### 派单模板

```
【proposal-writer】
活动：<名称>｜类型：<内部/对外>｜规模：<N人>｜日期：<YYYY-MM-DD>｜场地：<主+备选>｜人力：<N人>
必读知识库：skills/event-planning-kit/zhishiku/活动统筹全流程标准.md
  重点读：一（两类场景）、二之二（场地怎么定）、三（里程碑）、四（人员配置）、五（物料）
任务：撰写 一/二/三/四/五/六段 + 八段注意事项总纲
要求：流程到分钟、发言到人、物料含 10-15% 备用、分工表每个任务有唯一责任人+联系方式栏
回传：TASK_COMPLETE|PROPOSAL_WRITER|... 后附完整 Markdown

【budget-analyst】
活动：同上
必读知识库：zhishiku/预算标准.md —— 重点读 核心原则、二（支出构成）、三（单价表，只查涉及类别）、四（三档压缩）
可用额度：<用户给了就写金额，没给写"未指定">
脚本：skills/event-planning-kit/scripts/gen_budget_excel.py
任务：编制预算，调用脚本生成 Excel 到 output/预算/预算表_<活动名>.xlsx
要求：每项有采购来源；禁止"其他费用"；备用金=小计×10%
回传：TASK_COMPLETE|BUDGET_ANALYST|{活动名}|{类型}|{总额}元|{档位}|{Excel路径}

【risk-manager】
活动：同上
必读知识库：zhishiku/风险与应急预案标准.md —— 重点读 一（四类风险源）、二（分级）、五（按类型必备预案）
脚本：skills/event-planning-kit/scripts/gen_risk_excel.py
任务：识别风险并调用脚本生成 output/风险预案/风险预案_<活动名>.xlsx
要求：四类全覆盖；至少 1 条高风险；每条有唯一责任人；应急联络写成"谁在何时拿到号码"
回传：TASK_COMPLETE|RISK_MANAGER|{活动名}|{N}项（高a/中b/低c）|{联络完整?}|{Excel路径}

【promo-copywriter】
活动：同上
必读知识库：zhishiku/宣传文案标准.md —— 重点读 一（语气分档）、二（标题公式）、五（场景重点）
脚本：skills/event-planning-kit/scripts/gen_pptx.py
任务 Phase1：先产文案 JSON（标题/正文/slogan/副标题/信息/配色/话术），立即回传
任务 Phase2：再调脚本生成 output/宣传物料/宣传_<活动名>.pptx
回传 Phase1：TASK_COMPLETE|PROMOTION_COPYWRITER|COPY_DATA_READY|{活动名}|{JSON路径}|{标题}
回传 Phase2：TASK_COMPLETE|PROMOTION_COPYWRITER|{活动名}|{PPTX路径}
```

### 等待策略

| 收到什么 | 主理人做什么 |
|---------|-------------|
| PROPOSAL_WRITER 完成 | 记下流程节点数与物料项数，待用 |
| BUDGET_ANALYST 完成 | 记下总金额，准备与物料对账 |
| RISK_MANAGER 完成 | 检查是否有高风险项 |
| COPY_DATA_READY | **立即可以开始汇编 HTML**（不等 PPTX） |
| PPTX 完成 | 补下载链接到 HTML 附录 |

> 关键：不等所有成员全部完成才动。拿到 PROPOSAL + BUDGET + RISK + COPY_DATA 就可以开始汇编。

## Phase 2：汇编

### 步骤

1. **读骨架**：`skills/event-planning-kit/references/策划书-HTML骨架.html`
2. **读规范**：`references/HTML方案版式规范.md`（渲染规则在开头）
3. **读成员产出的文件**（不要从消息里复制，直接读文件，避免截断）
4. **填充八段**：
   - 封面头：名称 + Slogan + 四要素
   - 一~四段：来自 proposal-writer
   - 五段：流程表，**几行数据复制几行 `<tr>`**
   - 六段：物料表 + 场地布置 + 分工表 + 倒排
   - 七段：预算表，合计行用 `class="sum"` 放最后
   - 八段：注意事项 + 风险表（等级用 `lv-high/lv-mid/lv-low`）
   - 附录 A：宣传文案
   - 待确认事项：汇总所有推算/缺失项
5. **保存**：`output/策划书_<活动名>_<YYYYMMDD>.html`

### 汇编红线

- ❌ 不要重新设计 CSS（用骨架的）
- ❌ 不要在消息里粘贴全文（写文件）
- ❌ 不要漏掉"待确认事项"章节
- ✅ 所有 `{{ }}` 必须清干净

## Phase 3：交付前检查（9 项）

| # | 检查 | 判断方法 | 不通过怎么办 |
|---|------|---------|-------------|
| 1 | 预算合计 | 手算：Σ小计 + 小计×10% = 合计 | 退回 budget-analyst |
| 2 | 流程完整 | 有签到、有撤场、时间连续 | 退回 proposal-writer |
| 3 | 分工到人 | 每行有具体人名 | 退回 proposal-writer |
| 4 | 风险有高风险 | 至少 1 条标"高"，且含人员类 | 退回 risk-manager |
| 5 | 宣传一致 | 时间/地点/报名方式与方案相同 | 退回 promo-copywriter |
| 6 | 无残留占位符 | 全文搜 `{{` | 自己修 |
| 7 | 表格行数正确 | 与成员产出条目数比对 | 自己修 |
| 8 | 文件真实存在 | `ls` 检查 Excel/PPTX | 如未生成，如实说明，**不写假路径** |
| 9 | 待确认齐全 | 每个估算值都有对应条目 | 自己补 |

> 第 8 项是硬红线：**没生成就说没生成**，不能虚构路径。

---

## Phase 4：交付

### 必须做

1. `present_files` 打开 HTML（让用户直接看到成品）
2. 正文给**摘要**（不是全文）：
   - 文件路径
   - 八段要点（每段 1-2 句）
   - 预算合计与关键数字
   - 待确认清单
   - Excel/PPTX 路径

### 交付话术结构

```
✅ 已生成：<活动名>策划方案

📄 文件
- 策划书_xxx.html（主文件）
- 预算表_xxx.xlsx
- 风险预案_xxx.xlsx
- 宣传_xxx.pptx

📋 要点
- 主题 / 流程（N 环节，X 小时）
- 预算 ¥XXX（含备用金 XX）
- 风险 N 项（高 a / 中 b / 低 c）
- 宣传主标题「...」

⚠️ 待确认（N 项）
1. ...
2. ...
```

## 异常处理

| 情况 | 处理 |
|------|------|
| 用户信息不全且不肯补 | 按默认值推进，全部标待确认，交付时说明 |
| 某成员超时无响应 | 检查其是否在等知识库；如失败则用最小可用版本替代并说明 |
| 脚本报错（缺库） | `pip install openpyxl python-pptx` 后重试；仍失败则降级为 Markdown 表并说明 |
| 用户中途改需求 | 只重跑受影响成员，不整体重来 |
| 预算远超用户预期 | 不擅自砍，给三档方案让用户选 |

|------|------|------|
